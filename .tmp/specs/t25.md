## `src/trip/state.ts`
- `newTrip(pack, preference = 'balanced'): TripState` → `{packId, schemaVersion, preference, currentStep: 0}`.
- `applyIntent(trip: TripState, intent: Intent, resolved: {origin?: ResolveResult; destination?: ResolveResult}): TripState` — pure, returns a new object:
  - `new_trip`: start from `newTrip` (keep packId/schemaVersion; preference = intent.preference ?? 'balanced'), then apply slots.
  - `change_origin` / `change_destination`: apply that slot; clear `selected`, `currentStep = 0`.
  - `change_preference`: set preference (if given); clear selected/step.
  - `reverse`: swap originPlaceId/destinationPlaceId, clear selected, currentStep 0, clear pendingClarification. (Rerouting happens with the new endpoints; never reverse old steps.)
  - `clarify_answer`: if pendingClarification and candidates[choiceIndex] exists → set that slot's place id, clear pending, clear selected/step; otherwise unchanged.
  - `alternatives`, `ask_*`, `unrelated`: unchanged.
  - Slot application: resolved `status:'resolved'` → set `<slot>PlaceId`; `needs_clarification` → set `pendingClarification = {slot, text: <the mention text or ''>, candidates}` (do not change the slot); `unsupported`/`outside_ncr` → leave slot unset/unchanged. If both slots need clarification, origin first.
- `selectItinerary(trip, itinerary): TripState` → `selected = itinerary.ref`, `currentStep = 0`.
- `advanceStep(trip): TripState` → increments currentStep, clamped to `selected.steps.length - 1`; no selection → unchanged.

## `src/trip/restore.ts`
```ts
interface SavedTrip { packId: string; schemaVersion: number; originPlaceId: string; destinationPlaceId: string; preference: string; routeJson: string; currentStep: number }
validateRestoration(saved: SavedTrip, pack: Pack): { status: 'valid'; itinerary: Itinerary; currentStep: number } | { status: 'needs_replan'; reason: ReplanReason }
```
Check in this order, first failure wins:
1. `schemaVersion !== pack.manifest.schema_version` → `schema_changed`.
2. `parseRouteJson` fails → `invalid_route_json`.
3. Any step record missing (access→placeStops, leg→legs, walk→walks) or origin/destination place missing → `record_missing`.
4. Any step `eligibility === 'excluded'`, or origin/destination place not `accepted` → `record_ineligible`.
5. Any leg's route `suspended`/`retired` → `service_suspended`.
6. First step not an access of originPlaceId with direction `to_stop|both`, or last step not an access of destinationPlaceId with `from_stop|both` → `endpoint_mismatch`.
7. Middle chain not continuous with the same rules as search (leg board = current stop, walk from = current stop, no consecutive same-route legs, no consecutive walks, ≥1 leg, no repeated stop, no access steps in the middle) → `continuity_broken`.
8. `currentStep` outside `[0, steps.length - 1]` → `step_out_of_bounds`.
Valid → rebuild the `Itinerary` with the SAME builder search uses (export it from `src/route/search.ts`, e.g. `buildItinerary(steps, originPlaceId, destinationPlaceId, pack)`; refactor search to use it). A different `packId` with all records still valid is `valid` (records were revalidated). `preference` is not validated here.
