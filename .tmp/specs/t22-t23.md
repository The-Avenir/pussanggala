### `src/route/search.ts`
`searchItineraries(originPlaceId, destinationPlaceId, pack, opts?: {maxLegs?: number /*4*/, maxExpansions?: number /*50000*/}): {status:'ok'; itineraries: Itinerary[]} | {status:'no_route'; reason}`
- origin === destination → `same_place`. Origin place missing or not `accepted` or no originAccesses → `no_origin_access`; same for destination → `no_destination_access`.
- DFS from each origin access stop, deterministic order. Path rules: no repeated stop; two consecutive legs with the same `route_id` rejected; two consecutive walk links rejected; ≤ maxLegs legs; transfer between legs only at the same stop_id or via one walk link. Complete when the current stop has a destination access and ≥1 leg taken → steps `[access(origin), ...legs/walks, access(dest)]`. Keep exploring after a completion (longer alternatives allowed). Stop expanding at maxExpansions.
- Build `Itinerary` (contracts §7): `ref = {v:1, steps}`, `id = itineraryId(steps)`, rideCount, `transferCount = rideCount-1`, `routeIds` in order, `recordIds` = sorted unique of all access/leg/walk ids + route ids + fare ids used + stop ids + both place ids.
  - Fare: if every leg has ≥1 fare report → `{status:'known', min: Σ min(amount_min), max: Σ max(amount_max), currency:'PHP', conflict: any leg with >1 distinct (min,max) report, fareIds sorted}`; else `{status:'unknown', missingLegIds}`.
  - `reportedRideMinutes`: known iff every leg `ride_min` and every walk link and both accesses `walk_min` are non-null → sum; else unknown.
  - `walkMeters`: known iff every walk link and both accesses have `walk_m` → sum; else unknown.
- Dedupe identical ids. No route found → `no_route`.

T22 tests (`test/graph.test.ts`, `test/search.test.ts`, using the builder): direct one-leg trip; same-stop transfer across two routes; walk-link transfer; NO connection between two stops that are close/similar-named without a walk link; suspended and retired route excluded; excluded leg excluded; excluded access → no_origin_access; reverse direction not available unless a reverse leg exists; same-route consecutive legs rejected; consecutive walks rejected; cycle avoided; >4 legs not returned; fare unknown when one leg lacks fare (never 0); conflicting fare reports → range + conflict; time unknown when any component missing; same_place; outside/ambiguous origin → no_origin_access.

## T23 — `src/route/rank.ts` + `src/route/route.ts`
- Pareto filter: A dominates B iff A.rideCount ≤ B.rideCount AND both fares known with A.fare.max ≤ B.fare.min AND both times known with A ≤ B, with at least one strict. Any unknown on either side for fare or time → not dominated (unknown options stay visible).
- Sort by preference (tie-break always ends with itinerary id):
  - `lowest_fare`: known fare first by (min, max), unknown after; then rideCount; then known time asc (unknown after).
  - `fewest_transfers`: rideCount; then known fare min; then known time.
  - `shortest_reported_time`: known time asc, unknown after; then rideCount; then known fare min.
  - `balanced`: rideCount; then known time; then known fare min.
- Keep top 5.
- Comparisons over the final list (only when the condition holds; ties → no statement):
  - `lowest_reported_fare`: ≥2 itineraries with known fare; winner.max < every other known.min. `comparedIds` = known ones, `excludedUnknownIds` = unknown ones. text: `Lowest reported fare among N options with fare information.` + (if excluded) ` K option(s) have no fare information.`
  - `fewest_rides`: ≥2 itineraries; winner strictly fewer rides than all others. text `Fewest rides among N options.`
  - `shortest_reported_time`: ≥2 known; strictly less than all others. text `Shortest reported travel time among N options with time information (reported, not guaranteed).` + excluded sentence like fares.
- `route(originPlaceId, destinationPlaceId, preference, pack): RouteResult` = search → pareto → sort → top 5 → comparisons.
