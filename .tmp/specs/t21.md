## A. `src/resolve/resolve.ts`
`resolve(mention: PlaceMention, pack: Pack, trip?: TripState): ResolveResult` (types in `src/contracts/api.ts`, contracts §10).
- `trip_ref`: use trip.originPlaceId / destinationPlaceId; missing → `{status:'unsupported', reason:'no_trip_context', suggestions:[]}`; else place-id check with match `'trip_ref'`.
- `place_id`: unknown → unsupported/unsupported_place; else place-id check with match `'id'`.
- Place-id check: ncr_status `accepted` → resolved; `outside` → `{status:'outside_ncr', placeId, name}`; `ambiguous` → unsupported/ncr_unresolved.
- `text`: n = normalize(text). Empty → unsupported_place.
  1. n in `pack.ambiguitiesByNorm` → needs_clarification with those places (accepted only, max 4). If <2 accepted remain: exactly 1 → resolved match `'exact'`; 0 → unsupported/ncr_unresolved.
  2. n in `pack.aliasesByNorm` → place-id check, match `'exact'`.
  3. Fuzzy: optimal-string-alignment Damerau–Levenshtein in `src/text/distance.ts` (`osaDistance(a, b, max?)` with early exit returning `max+1` when exceeded). Compare n with every alias_norm in aliasesByNorm and every ambiguity norm. Threshold by n.length: <5 → no fuzzy; 5–8 → ≤1; ≥9 → ≤2. Collect distinct candidate places (an ambiguity-norm hit contributes all its places and forces clarification). Rank: distance asc, then place name, then place_id.
     - Accepted candidates: exactly one, from an unambiguous alias, no ambiguity hit → resolved match `'fuzzy'`; otherwise (≥2, or any ambiguity hit) → needs_clarification (top 4 accepted; if only 1 accepted due to ambiguity hit, resolve it as fuzzy).
     - No accepted candidates but ≥1 outside → outside_ncr with the best outside one. Only ncr-ambiguous ones → unsupported/ncr_unresolved.
  4. Nothing → unsupported/unsupported_place with `suggestions`: up to 3 accepted places having any alias that shares ≥1 token (token length ≥3) with n, ranked by osaDistance(n, alias) then name then id.
- `PlaceCandidate` = {placeId, name, area, kind} from PlaceRow.

## B. `src/intent/parse.ts`
`parse(query: string, trip?: TripState): Intent` — always returns an Intent with `source:'rules'`. Work on `q = query.toLowerCase()`; spans index the ORIGINAL query; `text` = original substring trimmed, span adjusted to the trimmed bounds. A mention ends at end of string, any of `?.!,;`, or a stop token (whole word): `na`, `po`, `lang`, `please`, `pls`, `using`, `via`, `instead`, or the start of a preference phrase. Strip a leading `sa ` / `ng ` / `the ` from a mention (span moves). Use regexes with the `d` flag for indices. Export keyword tables as consts (Member 3 will reuse them).

Detection order:
1. `trip?.pendingClarification` and the query is a choice → `clarify_answer` with 0-based `choiceIndex`: digits `1`–`9` → n-1; `first|una|yung una|unang` → 0; `second|pangalawa|ikalawa` → 1; `third|pangatlo|ikatlo` → 2; `fourth|pang-apat|pangapat` → 3.
2. Pair patterns → `new_trip` with origin + destination:
   - `(?:from|galing(?:\s+(?:sa|ng))?|mula(?:\s+sa)?)\s+X\s+(?:to|papunta(?:ng)?(?:\s+sa)?|hanggang(?:\s+sa)?|pa)\s+Y`
   - destination-first: `(?:how (?:do i |can i |to )?(?:get|go|commute) to|paano (?:pumunta|pupunta|makarating|mag-?commute)(?:\s+(?:sa|papunta sa))?|papunta(?:ng)?\s+sa)\s+Y\s+(?:from|galing(?:\s+sa)?|mula(?:\s+sa)?)\s+X`
   - bare `X to Y` only when nothing else matched and both sides non-empty after stop handling.
3. Keyword intents, first match wins in this order: new_trip (`new trip|bagong (?:biyahe|byahe|trip)|start over|ibang biyahe`), reverse (`reverse|pabalik|pauwi|balik|way back|return trip|going back`), alternatives (`other route|other option|alternative|ibang ruta|ibang daan|iba pa`), ask_fare (`magkano|how much|fare|pamasahe|bayad`), ask_boarding (`saan (?:ako )?sasakay|where (?:do i |to )?(?:board|ride|get on)|sakayan`), ask_transfer (`transfer|lipat|where (?:do i |to )?get off|saan (?:ako )?(?:bababa|baba)|bababa`), ask_hours (`anong oras|what time|hours|until when|hanggang anong oras|first trip|last trip|bukas pa|open`). Note "walang lipat"/"konting lipat" are preference phrases, not ask_transfer — check preference phrases before the `lipat` keyword.
4. Single endpoint: `(?:galing|mula|from)\s+(?:sa\s+)?X` → `change_origin` if trip exists, else `new_trip` with origin only. `(?:papunta(?:ng)?|pupunta|going to|to|sa)\s+Y\s+(?:na lang|instead)` or `(?:papunta(?:ng)?|pupunta|going to|go to|get to)\s+(?:sa\s+)?Y` → `change_destination` if trip exists, else `new_trip` with destination only.
5. Preference phrase alone → `change_preference` if trip exists (else `unrelated`). A detected preference phrase is also attached as `preference` to any intent above. lowest_fare: `cheapest|pinakamura|mura|lowest fare|tipid`; fewest_transfers: `least transfers?|fewest transfers?|konting lipat|walang lipat|isang sakay|direct`; shortest_reported_time: `fastest|quickest|pinakamabilis|mabilis`.
6. Else `unrelated`.
